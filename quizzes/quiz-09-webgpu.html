Quiz 09 — WebGPU et WGSL

1. Quel est le type vecteur 4 composantes flottant en WGSL ?

Correct ! En WGSL, le type est vec4<f32> ou sa forme courte vec4f. WGSL utilise des types explicites contrairement a GLSL.
Incorrect. En WGSL, on utilise vec4<f32> ou le raccourci vec4f pour un vecteur de 4 floats 32 bits.

2. A quoi servent les decorateurs @group et @binding en WGSL ?

Correct ! @group(N) @binding(M) identifie a quel bind group et a quel slot une ressource est liee, permettant au CPU de fournir les bons buffers/textures au shader.
Incorrect. @group et @binding identifient l'emplacement d'une ressource dans le bind group layout pour la liaison CPU-GPU.

3. Quel est le role du command encoder en WebGPU ?

Correct ! Le command encoder enregistre des commandes (beginRenderPass, dispatch, copyBufferToBuffer...) dans un command buffer qui est ensuite soumis a la GPU queue via queue.submit().
Incorrect. Le command encoder enregistre des commandes GPU dans un command buffer, qui est ensuite soumis a la queue pour execution.

4. Quelle est une difference majeure entre GLSL et WGSL en termes de syntaxe ?

Correct ! WGSL a une syntaxe inspiree de Rust : fn pour les fonctions, var/let pour les variables, types apres le nom (x: f32), et -> pour le type de retour.
Incorrect. WGSL utilise une syntaxe style Rust avec fn, var/let, et un typage explicite (param: type), contrairement a la syntaxe C de GLSL.

5. Comment obtient-on un GPUDevice en WebGPU ?

Correct ! On demande d'abord un adapter (representation du GPU physique) via navigator.gpu.requestAdapter(), puis on obtient un device (connexion logique) via adapter.requestDevice().
Incorrect. On obtient un GPUDevice en deux etapes : navigator.gpu.requestAdapter() pour l'adapter, puis adapter.requestDevice() pour le device.
