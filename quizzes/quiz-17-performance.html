Quiz 17 — Performance

1. Pourquoi le nombre de draw calls est-il un facteur critique de performance ?

Correct ! Chaque draw call necessite une validation d'etat cote driver et un envoi de commandes au GPU. L'overhead est principalement cote CPU. Regrouper les draw calls (batching, instancing) est essentiel.
Incorrect. Les draw calls sont couteux car chacun implique une validation d'etat et une communication CPU-GPU via le driver graphique.

2. Qu'est-ce que le LOD (Level of Detail) ?

Correct ! Le LOD utilise des versions simplifiees du mesh quand l'objet est loin (moins de triangles), et la version detaillee quand il est proche. Three.js fournit la classe THREE.LOD.
Incorrect. Le LOD affiche des versions plus ou moins detaillees d'un modele selon sa distance a la camera pour economiser des triangles.

3. Comment fonctionne le frustum culling ?

Correct ! Le frustum culling teste la bounding sphere/box de chaque objet contre les 6 plans du frustum. Si l'objet est entierement hors du champ, il n'est pas soumis au GPU. Three.js le fait automatiquement.
Incorrect. Le frustum culling elimine les objets hors du champ de vision de la camera avant de les envoyer au GPU, en testant leur bounding volume.

4. Pourquoi est-il important d'appeler dispose() sur les geometries, materiaux et textures ?

Correct ! Le garbage collector JS ne peut pas liberer les ressources GPU (VBOs, textures). Sans dispose(), la VRAM fuit a chaque changement de scene. Il faut disposer manuellement geometries, materiaux et textures.
Incorrect. dispose() libere les ressources GPU (VRAM) qui ne sont pas gerees par le garbage collector JavaScript, evitant les fuites memoire.

5. Quel est l'avantage d'utiliser un OffscreenCanvas avec un Web Worker ?

Correct ! OffscreenCanvas dans un Worker permet de deplacer le rendu WebGL/WebGPU hors du main thread, evitant que les calculs de rendu ne bloquent les interactions utilisateur (scrolling, clicks).
Incorrect. OffscreenCanvas + Worker deplace le rendu dans un thread separe pour ne pas bloquer le main thread et garder une UI fluide.
