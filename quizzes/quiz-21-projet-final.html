Quiz 21 — Projet final

1. Quel patron d'architecture est recommande pour organiser une scene 3D complexe ?

Correct ! Un scene graph hierarchique (parent-enfant) combine avec un systeme de composants (ECS : Entity-Component-System ou modules) permet une separation claire des responsabilites et une bonne scalabilite.
Incorrect. Un scene graph hierarchique avec des composants modulaires (ECS ou modules) est recommande pour les scenes complexes.

2. Comment implementer un terrain avec LOD (Level of Detail) ?

Correct ! Le terrain est divise en chunks via un quadtree. Les chunks proches ont une tessellation elevee, les lointains une faible. Des techniques comme le geomorphing ou le CDLOD lissent les transitions entre niveaux.
Incorrect. Le terrain LOD divise le terrain en tuiles (quadtree) avec une tessellation variable selon la distance a la camera.

3. Quelle approche est la plus efficace pour un systeme de particules massif (100k+) ?

Correct ! Pour 100k+ particules, on utilise un BufferGeometry (Points ou InstancedMesh) avec les positions dans un Float32Array. Idealement, la simulation tourne dans un compute shader GPU pour zero overhead CPU.
Incorrect. Un systeme de particules massif utilise des BufferGeometry avec attributs personnalises et idealement un compute shader GPU pour la simulation.

4. Qu'est-ce qu'un frame budget et pourquoi est-il important ?

Correct ! A 60 FPS, chaque frame dispose de 16.67ms. Ce budget est reparti : physique (~2ms), logique (~2ms), rendu (~10ms), overhead (~2ms). Depasser le budget cause des drops de framerate.
Incorrect. Le frame budget est le temps maximum par frame (16.67ms a 60 FPS), reparti entre les differentes taches de simulation et rendu.

5. Quelles sont les bonnes pratiques de gestion memoire pour une application 3D web ?

Correct ! Bonnes pratiques : dispose() des geometries/materiaux/textures, object pooling pour eviter le GC, pre-allocation des typed arrays, monitoring de renderer.info pour les fuites, et destruction propre lors de la navigation.
Incorrect. Il faut disposer les ressources GPU, utiliser des pools d'objets, pre-allouer les buffers et monitorer la memoire GPU.
